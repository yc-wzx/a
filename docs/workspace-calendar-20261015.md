# 工作台日历（2026-10-15）

本次按已确认的日历方案扩展现有工作台，面向课程项目中的个人时间安排与敏捷任务推进。

## 使用方法

1. 登录后进入工作台，在「我的工作」使用「日历」；切换「任务列表」可继续按项目、关键词和截止时间检索任务。
2. 默认按周查看，使用「月」「事项」切换显示方式。事项视图显示两周，月视图完整读取 42 天；日期箭头、「今天」和小月历用于定位日期。
3. 勾选三类内容：课程与日程、工作安排、截止节点。选择某日后，右侧列出该日事项。
4. 点击任务或工作安排，在当前工作台打开既有任务详情侧栏；点击迭代进入对应迭代。打开个人安排的原管理页面可补充临时日程、核对和重新规划。
5. 工作计划显示「需要重新核对」时，在原个人规划页核对后重新确认。日历不自动调用 AI，不自动改动计划和团队截止日期。

## 数据规则

| 内容 | 读取已有数据 | 显示方式 |
| --- | --- | --- |
| 本人课表与临时事务 | `personal_schedule_events`，实际与可见范围重叠的记录 | 北京时间的实际时段；跨午夜在相邻日期分别显示，重叠安排并排 |
| 本人工作安排 | `personal_work_plans` 中已确认计划 | 仅保留当前仍指派给本人、未完成且项目可访问的任务；使用当前任务标题 |
| 任务截止 | 本人在有效团队、未归档项目中的未完成任务，含子任务 | 日期节点；不生成虚构的工作时段，无日期任务保留在任务列表 |
| 里程碑／项目截止 | 当前有权访问的未归档项目 | 日期节点，已完成里程碑注明状态 |
| 迭代 | 当前有权访问且与范围重叠的迭代 | 起止日期范围，已结束迭代注明完成状态 |

私人课表和工作安排只对当前账号返回。教师与负责人也不能通过此接口读取学生私人事务。团队忙闲继续使用原有共享设置与脱敏接口，未增加公开具体事项的规则。退出团队、撤销成员资格或归档项目后，新查询排除对应项目内容。

旧计划的核对状态复用个人规划器的完整快照校验，涵盖任务、依赖、项目节点、日程与偏好变化；不只比较日程版本号。草案、取消计划不进入日历；完成、删除或改派任务不会从旧计划重新显示为待做工作。

读取接口为 `GET /api/workspace/calendar?startDate=YYYY-MM-DD&endDate=YYYY-MM-DD`，身份只取登录会话，禁止公共缓存。范围最多 42 天；超出记录上限明确返回 `truncated` 并在页面提示，不能将不完整数据用于判断空闲。读取失败显示可重试的错误，不伪装成零记录。

## 实现范围

复用原数据库、登录、任务侧栏、日程管理和个人规划器，无数据库迁移、无新依赖。保留工作台统计、下一步任务、项目、个人资料入口、教师反馈和新手教程，并同步更新正式使用指南。

不增加外部日历授权、会议系统、日程拖拽写入、自动重排、团队绩效排名。空白只表示没有登记，不表示学生空闲。

## 验证

隔离 PostgreSQL 测试覆盖私人记录、教师可见范围、撤销权限、旧计划失效、任务完成与改派、取消草案、超过 50 条记录及截断上限。日期测试覆盖北京时间、跨午夜、跨年、月底与重叠布局；接口测试覆盖未登录、伪造账号和私有响应。

电脑 Edge 共 16 组检查通过：三类筛选、日期联动、周／月／事项切换、任务单侧栏、原任务列表、刷新、断网重试与三个角色。浏览器采用美国时区，核对页面仍按北京时间显示；检查 1440、1280、1024 像素宽度。结果见 [电脑操作检查](verification/calendar-local-20261015.json)。

完整回归 795 项通过、2 项按原配置跳过；随后完善多日时段的日期标签，最终 22 项日历、接口与工作台专项再次通过。TypeScript、生产构建与 ESLint 检查通过。统计见 [测试记录](verification/calendar-tests-20261015.json)。没有调用真实外部 AI，未进行移动端适配验收。
