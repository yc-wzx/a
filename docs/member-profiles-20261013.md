# 团队成员个人主页

本轮在 AgileCampus 原代码上增加成员个人主页，电脑网页为展示范围。功能默认面向共同团队中的师生与成员，复用现有任务、成果、项目和活动记录，不建立第二套贡献数据。

## 怎么使用

- 团队 → 成员：成员以卡片展示头像、姓名、角色、简介和技能。可按姓名、技能或角色筛选，点击姓名、头像或「查看个人主页」进入。
- 账户菜单 → 我的主页：查看自己的介绍、项目、任务与正式成果。自己的主页提供「编辑个人资料」，可修改姓名、简介、技能和站内头像的颜色与文字。
- 项目概览 → 成员工作量：保留原任务入口，同时提供「查看个人主页」。工作台快速查找也可打开自己的主页。

主页有三个分区：

| 分区 | 内容 |
| --- | --- |
| 概览 | 个人介绍与自填技能；共同团队角色；参与项目与负责人职责；任务／成果数量；最多 10 条真实近期项目操作 |
| 任务 | 实际指派给该成员的任务；待开始、进行中、完成、逾期筛选；每页 20 项；点击进入原任务详情 |
| 成果 | 已正式提交的报告、PPT、视频等材料及审核状态；最近 20 项；点击进入原成果详情和正式版本记录 |

个人资料由本人维护，团队角色继续由原成员管理操作维护。修改姓名后，主页、成员卡片、账户菜单和工作台显示数据库中的最新姓名。技能用于分工参考；任务数量包含子任务，不作为工时或贡献评分。

## 数据范围与隐私

- 访问其他成员必须当前仍有共同团队。主页仅查询这些共同团队中的项目和记录；从成员卡片进入时保留当前团队范围。
- 未登录跳转登录；无共同团队、非法标识或不属于双方的团队范围返回 404。没有团队的本人可以查看真实空状态并编辑资料。
- 各列表和统计共用同一权限范围。读取期间锁定共同成员关系，避免撤销成员权限与聚合查询交叉；不能通过任务筛选或翻页扩大范围。
- 主页不读取个人日程、完整个人工作计划、文档正文、AI 会话、密钥、令牌、密码、邮箱或飞书身份。成果草稿和未提交的修改内容不进入主页，正式材料仍由原成果页权限校验。
- 最近活动来自既有 `project_activities`，不根据更新时间猜测工作或补造历史；不呈现评论正文、阻塞原因等私密输入。
- 个人编辑只能从登录会话确定本人；拒绝夹带目标用户、密码或角色等字段。首次保存与后续保存均校验资料版本，其他窗口的旧稿不会覆盖新稿。校验失败保留已输入内容。

## 开源参考与实现

参考了 [Plane 的个人概览](https://github.com/makeplane/plane/blob/preview/apps/web/app/%28all%29/%5BworkspaceSlug%5D/%28projects%29/profile/%5BuserId%5D/page.tsx)的统计和活动组织方式，以及 [HuangLuofei/Agilecampus](https://github.com/HuangLuofei/Agilecampus/blob/main/src/app/%28app%29/settings/profile/page.tsx)的自填技能用于分工的思路。头像和分区参考 [shadcn/ui](https://github.com/shadcn-ui/ui)的组件组合方式。

本轮按本项目接口独立实现，没有复制第三方业务代码，也没有引入运行依赖。沿用 Next.js、Drizzle、React、Tailwind 和 Lucide。新增 `user_profiles` 表保存简介、技能、头像和资料版本，通过 `0018_member_profiles.sql` 增量迁移，不修改原账号凭据列。
