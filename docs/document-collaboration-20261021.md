# 文档协作升级与操作说明

入口：项目 → 项目文档 → 打开一篇文档。本次在已有 Tiptap／Yjs、文档权限、附件、任务和站内通知基础上增量实现 F1、F2、F3、F4、F5、F7。

| 功能 | 怎么使用 | 实际行为 |
|---|---|---|
| 正文 @ | 在正文输入 `@` 和关键词，或点工具栏 @；选择成员、文档或任务 | 成员使用稳定账号 ID；文档沿用原引用和反向引用；任务显示当前名称、状态、负责人和日期，点开现有居中任务详情 |
| 正文提醒 | 选成员前勾选“提醒被 @ 的成员”，插入后点“保存并提醒” | 先同步正文，再校验当前权限、版本、段落及实际提及；站内通知定位到原段落，重复请求不会重复发送 |
| 评论 @ 与编辑 | 在评论／回复输入 @，从成员列表选择并发布；自己的评论下点“编辑” | 编辑框显示姓名，保存稳定身份；通知定位具体评论；只允许作者改正文，检测并拒绝覆盖他人已修改内容 |
| 图片与附件进正文 | 把截图粘贴／拖进正文，或点上传图标选择图片、PDF、PPT 等 | 沿用现有 20 MB 类型、额度和权限规则；图片直接显示，其他附件提供打开和下载；失败可重试，上传后原段落被删会明确提示 |
| 块拖动 | 鼠标移到内容块旁，拖六点把手到目标上下方 | 落点有指示，段落、列表、表格整体移动并保留标识；远端删除了源或目标时取消操作；原上下移动及快捷键保留 |
| 文内查找替换 | 点“查找正文”，或正文内按 Ctrl+F；输入词语、上一处／下一处；编辑者可替换 | 高亮最多 1000 处匹配；可跨文字格式，不跨成员／任务等引用节点；全部替换有数量确认，撤销只回退本次替换 |
| 阅读／编辑／专注 | 在文档顶部切换模式，点“专注阅读”扩大正文；再次点击或 Esc 退出 | 阅读隐藏编辑工具并停止正文写入，保留获准评论；专注隐藏页面导航；模式不改变服务端权限 |

## 权限和数据边界

- @ 不会授予阅读、评论或编辑权限，候选成员只包括本来能访问该文档的人。
- 被撤权或已离开项目的引用不会继续显示个人资料；私密文档不通过通知正文或外部渠道扩散。
- 文档及任务名称在查看时解析；任务状态定期刷新，只有一份正式任务，不在文档中绕过提交及审核。
- 附件仍属于当前文档，读取时重新鉴权；移除正文卡片不会自动删除原附件，清理由现有附件列表完成。
- 图片和文件在当前段落后插入。多文件一次先处理首个；较大的批量文件继续通过附件区上传。
- 查找只处理当前正文，不改评论、历史版本或引用 ID；替换不会破坏链接、任务卡片和成员身份。
- 代码无需数据库迁移，也没有更换个人 AI 配置或演示账号。

## 接口增量

- `GET /api/projects/:projectId/documents/:documentId/collaboration`：返回当前允许提及的成员、项目任务当前信息及本文档附件，不缓存。
- `POST /.../:documentId/mentions`：`{requestId, expectedRevision, epoch, blockId, userIds}`；只有当前编辑者可调用，目标必须仍出现在相应正文块中且有文档权限。
- `POST /.../:documentId/comments`：评论正文中的选人标记保存为 `@[显示名](member:账号ID)`，界面显示当前姓名，服务端校验选人范围。
- `PATCH /.../:documentId/comments`：保留原解决／重新打开接口；新增 `{requestId, commentId, body, expectedBody}`，只允许作者修改并检查原正文一致。
- 文档节点新增 `documentMention(userId)`、`documentTaskReference(taskId)`、`documentAttachment(attachmentId)`；不保存可伪造的姓名或任务标题。新引用在同步时按当前项目、文档及权限检查。

## 验证

- 真实 PostgreSQL 回归包括私密文档选人、跨项目任务／跨文档文件拒绝、提醒幂等、过期版本、撤权、评论编辑冲突、任务状态变化、协作节点往返、块标识及跨格式查找。
- 桌面浏览器逐项操作正文 @、通知、文档与任务引用、居中详情、本地图片上传、查找替换及撤销、拖动、模式切换、评论 @／作者编辑，并刷新验证引用与图片保留。
