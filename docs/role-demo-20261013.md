# 三角色课堂演示准备

2026-10-13 已在 [AgileCampus 正式网站](https://weidu-agilecampus.pw/login) 创建教师、学生、团队管理员三个持续保留的演示账号。账号密码和具体操作链接通过私有的《AgileCampus演示账号与展示流程.md》交付，公开仓库不保存登录密码。

演示团队为「唯笃队·课堂演示（模拟数据）」，主项目为「AgileCampus 全功能演示（模拟数据）」。任务、材料、反馈和会议记录均明确标注为模拟数据，不作为实际开发进度或真实测试结论。原有团队与个人配置保留。

## 各账号展示什么

| 角色 | 主要流程 |
| --- | --- |
| 团队管理员（admin） | 查看工作台、团队与项目统计；管理成员和项目；展示里程碑、任务分工、依赖、迭代、资源、公告与过程记录 |
| 学生 | 查看和更新自己的任务；使用检查项、关注与资料；编辑文档、提交成果、根据反馈修改；管理个人日程并生成规则计划 |
| 教师 | 查看教师总览、风险和待审成果；审阅正式版本、评论文档、发布公告；查看获准共享的模糊忙碌时间 |

管理员是团队内的管理角色。演示学生同时担任主项目负责人。多人展示使用三个不同浏览器或独立浏览器配置文件，避免覆盖登录状态。

桌面交付还包含课表 CSV、ICS 和文档 Markdown 模拟文件，可先预览再导入。课表样例日期为 2026-10-15／16，后续展示需要更新日期。

## AI 的展示范围

按负责人要求，三个账号均不配置真实模型密钥，也不借用其他人的助手。展示个人设置入口和规则规划；规则计划由现有业务逻辑真实生成。模型聊天、文档选区生成和真实飞书送达需要之后各自配置，并另行验证。

未选入的 4／6／7／8／9／D6 保持此前范围，见 [本批上线说明](course-live-20261013.md)。

## 准备和验证

- 先在独立本地测试数据库预演，再备份正式数据库后执行。创建通过现有团队、任务、迭代、文档、成果、日程等业务服务，使用真实权限、状态转换和记录。
- 正式库从 16 位用户、9 个项目、8 项任务增加到 **19 位用户、11 个项目、23 项任务**；迁移账本仍为 18 条，原数据库容器保留。
- 三个独立电脑浏览器登录正式网址，核对演示目录、任务三视图、文档权限和版本、成果状态、迭代、规则计划、日程隐私、资料、资源、周报、通知及个人设置。结构化结果见 [演示验证记录](verification/role-demo-20261013.json)。
- 现场预演发现：从已打开的规划页面点击重新规划时，查询参数改变但表单状态沿用，原任务未自动勾选。生成表单现在按项目和原计划标识重新初始化，带入原目标、任务、工时与方式；回归脚本覆盖该页面跳转。
- 修复后的本地电脑浏览器专项 15 项通过，包含导入、事件编辑／删除、规则草案、避开课程、确认／取消、原子重新规划、共享撤回和隐私权限；任务原状态保持。TypeScript 与相关 ESLint 通过。本轮未要求手机端验证。

演示账号和数据持续保留供课程展示使用，后续现场编辑、审批、恢复、删除会真实改变模拟数据。需要重复演示时可新建样例或使用已有历史记录，不重置整个数据库。

## 初始化脚本

[scripts/seed-role-demo.ts](../scripts/seed-role-demo.ts) 供维护者准备这一组演示数据：

1. 使用当前应用的迁移构建环境与数据库连接；TypeScript 需先通过现有 esbuild 打包为 Node ESM，保留外部依赖和 `createRequire`，运行时放在可解析应用依赖的位置。
2. 凭据由标准输入传入，结构为 `origin` 和三个 `accounts`；账号包含角色、邮箱、名称和密码。密文／明文凭据文件均不提交仓库，不把密码放在命令参数中。
3. 需设置 `AGILECAMPUS_DEMO_SEED=authorized`；正式来源必须与 `AUTH_URL` 一致，角色和演示邮箱名单固定。
4. 任一演示邮箱已存在即拒绝覆盖；不会重设现有密码。失败回滚只处理该次运行新建的用户与演示团队，未调用全库清空工具。
5. 输出阶段与不含密码的清单。已成功执行的正式库不要再次运行初始化脚本。
