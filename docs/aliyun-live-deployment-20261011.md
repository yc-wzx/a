## 现在怎么用

网站：**[https://agilecampus-47-242-210-133.sslip.io](https://agilecampus-47-242-210-133.sslip.io)**

这是免费临时域名，由 sslip.io 解析到已有的香港服务器。后续购买自己持有的域名时可以替换；现在无需额外购买域名。原 IP 的浏览器入口转到此地址，IP 健康检查仍保留。

1. 打开网站，选择「去注册」，填写自己的姓名、邮箱和密码。
2. 登录后进入「团队」，创建「唯笃队」。创建人自动成为该团队管理员。
3. 将团队邀请码发给同学；同学注册后凭邀请码加入。
4. 在团队的「成员管理」中核对成员角色，需要时把指导老师设为导师。
5. 在团队的「项目」中创建课程项目，选择课程模板，再登记真实任务和负责人。

没有公开默认管理员账号。线上验收使用了明确标为「部署验收示例」的私有账号和项目，你们新注册的账号不会加入这些示例团队。它们不代表团队实际进度。

负责人已确认新网址在电脑上能够打开。新入口的 31 项浏览器验收在当前 Windows 电脑经现有代理完成；关闭代理的直连仍然超时，手机流量和老师实际网络尚未确认。把地址发给老师前，请用手机关闭 Wi-Fi、通过流量再试一次。

## 这次访问异常的处理

校园电脑打开 IP 地址时报 `ERR_CONNECTION_CLOSED`。独立公网复查时，22、80、443 端口可连接，应用、数据库、提醒和代理均运行正常，公网证书校验通过。当前电脑经代理用 IP 连接失败，改用域名作为连接目标后，同一服务器返回正常健康响应；关闭代理的连接仍超时。

已配置域名的可信 HTTPS 证书，同步修改 `AUTH_URL`、`AGILECAMPUS_URL` 和代理地址，避免登录回调跳回原 IP。配置切换前保存原 `.env`，应用镜像、数据库密码及其他秘密保持不变，配置失败会恢复原环境。没有执行数据库迁移或重新创建数据库。

## 负责人怎样维护

从阿里云轻量服务器控制台选择「远程连接」，使用已经能登录的 Workbench。下面的命令在**服务器终端**运行。

查看服务：

```bash
sudo /opt/agilecampus-runtime/node/bin/node /opt/agilecampus/scripts/ops.mjs status
```

检查应用和数据库：

```bash
sudo /opt/agilecampus-runtime/node/bin/node /opt/agilecampus/scripts/ops.mjs smoke
```

做一份手动备份：

```bash
sudo /opt/agilecampus-runtime/node/bin/node /opt/agilecampus/scripts/ops.mjs backup
```

备份在服务器的 `backups` 目录。目前每次发布前会自动备份，日常定时备份尚未配置。正式登记重要材料后，也应做备份并保存一份到服务器之外。

以后更新代码仍使用仓库的预构建发布流程，确保源码与镜像版本匹配，并保留服务器现有 `.env`。不要重新生成已经使用中的数据库密码。完整升级、独立恢复和代码回退步骤见[部署与恢复方案](aliyun-deployment.md)。本次没有实际执行代码镜像回退。

本次临时放入 GitHub Secrets 的部署 SSH 密钥和生产配置已经移除。以后使用 SSH 部署或服务器验收工作流前，需要由负责人临时配置相应 Secrets；公开网页浏览器验收不需要部署密钥。
