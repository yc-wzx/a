# 体验问题处理记录（2026-10-19）

依据《AgileCampus-体验问题汇总.docx》，逐项与当前代码核对。适用范围仍是高校师生、桌面网站、轻量敏捷协作。反馈文件是参考资料，不能代替此前确定的产品范围。

## 本轮修改

| 体验问题 | 处理方式 |
|---|---|
| 所有项目找不到创建入口 | 增加“创建项目”，列出本人可以管理的团队，复用原有项目模板与权限。无管理员资格时说明原因。 |
| 项目简介、日期、归档没有入口 | 增加固定“项目设置”。管理员可以修改、归档、恢复；校验日期和版本，避免旧窗口覆盖新设置。 |
| 无法清理测试项目 | 归档后可以永久删除。先展示任务、文档、成果、迭代、资料数量，再输入完整项目名确认；包含私有项目文档、该项目个人计划、项目助手会话与项目记忆，不能恢复。删除前再次鉴权、核对预览，保留成员账号和个人课表。 |
| 归档后部分功能仍能写入 | 补齐成果、公告、里程碑的服务限制；归档后仍可阅读，恢复后继续协作。 |
| 成员管理入口不完整 | 增加邀请入口、角色操作反馈、退出和移除。最后一名管理员不可离开或降级；成员有未完成分工或仍是活跃项目负责人时，先完成交接。已提交内容和作者记录保留。 |
| 关闭任务会丢内容 | 任务字段、成果草稿、团队评论和任务讨论草稿纳入离开保护；支持关闭、Esc、遮罩、站内跳转、返回和刷新等入口。 |
| 保存其他区域会覆盖正文 | 正文字段编辑时保持原表单；保存期间锁定字段。并发冲突保留输入，需明确放弃字段修改后载入最新版本。 |
| 周报、过程证据标题正文重复 | 仅隐藏与标题相同的正文，网页和 Markdown 导出一致；保留额外解释及不同事件，不删除业务记录。 |
| 迭代完成比例挤在一起 | 明确显示“完成 n/m（百分比）”。 |
| 看板拖动范围不清、键盘不可操作 | 独立拖动把手，提供中文按键说明、键盘跨列和“移动至”菜单；进行中列衔接全项目主任务数量提醒。 |
| 创建任务不能直接加入迭代 | 简化为可展开的新建入口，支持任务池或未结束迭代；任务创建和入轮在同一幂等事务内完成，失败不留下半成品。 |
| 文档无限加载、弱网恢复困难 | 请求有超时；同步失败逐步延长重试间隔，保留当前页面待同步内容。编辑器出错或连接中断可阅读已鉴权正文副本、下载或重试。 |
| 单文档仍显示“第1页” | 仅在确实需要翻页时显示页码。 |
| 教师总览不能主动刷新 | 增加刷新数据操作。 |
| 同一迭代每天重复显示 | 周历显示一个跨天区间，月历按周裁切；所选日期明细仍展示相关迭代。 |
| AI 入口重复挤占任务页面 | 移除任务页内嵌的整块聊天，保留明确的项目助手入口；文档 AI 和个人规划继续作为场景操作。不会合并或公开私人会话。 |
| 规划按钮禁用却不说明原因 | 明确提示先选择本人任务；未选项提示“勾选后填写”，简化默认短期目标措辞。 |
| 课表页面一次堆放大量表单 | 分为已登记日程、添加与导入、可投入时间、共享设置四个区域；切换保留页面内的表单状态。 |
| 旧教程、技术文案影响理解 | 项目简介引导改为真实设置入口；风险卡显示中文观察值，增加主要页面的浏览器标题和加载/重试状态。 |

## 核实后保留现有能力

- 团队角色调整、任务依赖、@ 成员、全队评论、任务成员私密讨论、回复和未读提示已经存在，不重新造一套。
- 结束迭代前已有已完成/未完成任务数量与去向确认，保留现有流程。
- 个人规划已有“不调用 AI”的规则模式；继续允许用户不配置密钥就使用规则规划。
- 文档正文已经有自动保存、版本、权限和断线队列，本轮补恢复交互，不替换协作引擎。
- 主任务、含子任务、成果审核是不同统计口径，不能为了让百分比相同而修改事实。

## 暂不加入的内容

| 建议 | 决定与原因 |
|---|---|
| 手机适配 | 延续此前“仅做桌面网站”的约定。 |
| 学校共用 AI 密钥、统一额度 | 延续每个人配置自己助手的约定，避免个人请求、账单和记忆混在一起。 |
| 代码托管、PR 审核系统 | 使用已有 GitHub 仓库链接，课程平台保留任务与成果管理。 |
| 完整项目群聊、微信/邮件全渠道推送 | 先使用已有团队评论、任务讨论、站内通知；不扩成即时通信软件。 |
| 全功能网盘、直接上传大视频 | 当前资料和成果以链接关联。附件需要单独的存储目录、鉴权、容量限制和文件备份，不能只加上传按钮。视频继续使用外链。 |
| ICS/外部日历双向同步 | 当前导入方式保持；完整重复课程、更新冲突和时区同步需要独立验收。 |
| 浏览器崩溃后恢复未保存正文 | 当前待同步内容保留在页面内；正文副本可下载。没有实现持久离线缓存，不能承诺关闭浏览器后恢复。 |
| 解散整个团队、复杂邀请审批 | 本轮完成项目生命周期及成员交接，不扩大到删除整个组织和校级审批。 |

## REA 参考与边界

REA 记录来自官方公开页面、页面文字与截图，没有登录商业产品账号；以下是可借鉴的交互模式，不是其私有源码或内部实现证明。

- [Jira 项目详情设置](https://support.atlassian.com/jira-cloud-administration/docs/edit-a-projects-details/)和[项目归档](https://support.atlassian.com/jira-cloud-administration/docs/archive-a-project/)：固定管理入口、归档说明和恢复路径。
- [Jira 键盘操作](https://support.atlassian.com/jira-software-cloud/docs/use-keyboard-shortcuts/)：任务与列之间可以通过键盘操作；本项目具体按键和移动菜单由现有看板实现。
- [Notion 日历视图](https://www.notion.com/help/calendars)：跨天事项保留一个事件身份，以日期区间呈现。
- [Notion 保存与连接错误说明](https://www.notion.com/help/notion-error-messages)：区分加载、保存、离线等状态，不把失败长期显示为连接中。
- [飞书文档本地记录说明](https://www.feishu.cn/hc/en-US/articles/360046996234-docs-local-record-faqs)：区分当前本地内容与已经同步到云端的记录，提供内容保留和恢复路径。

原始 REA 证据、源码摘录和浏览器回归产物保留在本地 `feedback-20261019` 研究目录。修复以本项目的权限、数据保护和实际测试为准。
