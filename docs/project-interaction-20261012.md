# AgileCampus 项目交互改进：已选 1、2、3、5

本轮在原代码上增量开发，只实现负责人确认的四项。原任务状态、业务接口和角色权限沿用，不引入新产品框架或数据库迁移。电脑网页是本轮验收范围。

## 新增功能和怎么使用

| 候选 | 已实现 | 入口和操作 |
| --- | --- | --- |
| 1：任务三视图 | 看板、列表、甘特图；共用指派人、优先级、标签、阶段、逾期筛选和同一个任务详情；列表支持三种排序 | 项目 → 任务，点击视图按钮；点击列表标题、甘特横条或未排期任务打开详情。原时间线地址自动转到甘特图，保留 URL 筛选 |
| 2：成员工作量 | 每人实际未完成、已完成、逾期数量；前三项待处理任务；未指派任务单列 | 项目 → 概览 → 成员工作量；展开成员，点击任务或全部任务进入对应列表 |
| 3：常用筛选 | 保存当前筛选、分组、视图、列表排序；应用、重命名、删除；最多 12 个，每个名称最多 30 字 | 项目 → 任务 → 展开常用筛选；起名保存；以后选中名称并应用 |
| 5：项目侧栏 | 左侧固定导航、项目名称、当前位置；次级分区可展开；原路由和日历下载保留 | 项目内任何页面；「协作」包含公告、会议资料、个人助手，「成果与记录」包含成果、周报、过程证据 |

常用筛选仅存当前浏览器，按登录账号和项目分开。更换设备、清除站点数据后不会保留；关闭站点存储时明确提示保存失败，当前筛选仍可用。保存内容不包含任务正文、个人课表、API 密钥或正在打开的任务编号，也不会扩大后台权限。

成员工作量按本项目每一条任务记录统计，主任务、子任务各计一次；已完成不计逾期，当天截止不算逾期，按北京时间判断。数量不等于工时或贡献评分。它不查询课程表，不显示私人事件。其他概览卡片原来的“主任务完成率”口径保持，页面注明区别。查询故障显示不可用，不用零冒充成功。

管理员和学生按原规则操作任务，老师可查看和指导，归档项目不可编辑。每个页面和任务操作仍检查实时项目权限；侧栏没有放宽权限。任务详情由 URL 的 task 参数驱动，切换展示设置不丢筛选或任务定位。

## 参考与实现方式

- [Bingz-Netizen/AgileCampus-](https://github.com/Bingz-Netizen/AgileCampus-)：借鉴三视图和成员任务概况的交互思路。
- [HuangLuofei/Agilecampus](https://github.com/HuangLuofei/Agilecampus)：借鉴团队／项目入口集中在侧栏的方式。
- [RETEMPT/AgileNest](https://github.com/RETEMPT/AgileNest)：借鉴给筛选组合起名、保存个人视图的方式；本轮简化成浏览器保存，不搬其多组织和多状态模型。

上述为设计参考，本轮没有复制其他同学的实现代码；统计、URL 状态、本机存储和导航按本项目接口自行实现。沿用已有 Lucide 图标和 dnd-kit 看板，不新增运行依赖。其余候选 4、6–12 没有记作完成。
